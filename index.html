Veena's Conditional Access Simulator

A sandbox for policy evaluation logic. No tenant, no tokens, no real data — everything runs in your browser.

How it decides

Every enabled policy whose conditions match the sign-in is in scope. From there:

  • A block from any matching policy wins outright. Nothing overrides it.
  • Otherwise the grant requirements of all matching policies stack — and each is resolved against the sign-in where the sign-in can answer it.
  • A requirement the sign-in can answer and fails — an unmanaged device facing a managed-device requirement — is a denial, not a prompt.
  • A requirement it cannot answer — whether the user can complete MFA — is reported as a challenge.

Four verdicts, not two: allowed, blocked, blockedUnsatisfiable, challenge. The full design is in docs/phase1-spec.md.

Roadmap

  1. Evaluation engine — four verdicts, with a per-policy explanation trace. Done.
  2. Policy editor — create, edit, enable/disable and delete rules.
  3. Sign-in builder — device, trust, location, risk, app sensitivity.
  4. Result panel — the verdict, plus which policies applied and which did not.
  5. Persistence — export and import a policy set as JSON.
